HNSW Graph Parameters & Guarantees

The vector store configures a Hierarchical Navigable Small World (HNSW) graph index optimized for high-dimensional cosine similarity:

  • • M = 16: Maximum outgoing connections per node across graph layers.
  • • ef_construct = 100: Dynamic candidate priority queue size during index construction.
  • • search_ef = 64: Search-time exploration candidate size for logarithmic recall.
  • • Metric = Cosine: Normalized inner product in \(\mathbb{R}^{384}\).

Why HNSW + N-ary Trees (vs B-Trees)

Traditional databases use B-Trees for 1D scalar intervals (e.g. timestamps, integer keys). When scaled to 384 dimensions, B-trees collapse due to the Curse of Dimensionality and degrade to \(O(N)\) linear scans.

AMHIE solves this by pairing:

  • 1. C++ N-ary Tree: Handles deterministic hierarchical layout and page-child containment.
  • 2. Qdrant HNSW: Handles high-dimensional fuzzy semantic similarity in \(O(\log N)\) time.

Ingestion Mathematical Formulation

Visual Dominance Score (VDS)

Ratio of table & figure area to total page dimensions:

VDS = (Area_Tables + Area_Images) / Page_Area
Scaled Token Density (Td)

Compactness of linguistic tokens per unit surface:

Td = (Words * 1.3 / Page_Area) * 10^4
Layout Complexity (Lc)

Multi-column & element boundary penalty:

Lc = (N_text*0.4) + (N_tab*3.5) + (N_img*1.5)
Continuous Complexity Score (CS)

Weighted multi-objective decision:

CS = 0.35*VDS + 0.35*Elems + 0.20*Lc + 0.10*Td
Decision Criterion:

• If \(CS < \tau\) (\(0.45\)): Page is retained as a unified Coarse Parent Node. No micro-chunks are stored in Qdrant.

• If \(CS \ge \tau\) (\(0.45\)): Page is decomposed into an N-ary Subtree containing dedicated child nodes for structured Markdown tables and images.
